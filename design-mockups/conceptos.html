Rediseño del portfolio — 3 conceptos

Tres maneras de que la web se lea como "programador" a primera vista, sin tocar la estructura de secciones ni el contenido: Hero real (tu nombre, tu GitHub, tus 3 proyectos) dentro de un marco de navegador, y debajo una tira con las tarjetas de proyecto en el estilo de cada concepto.

Qué cambia:
  • Tipografía 100% mono en toda la web (una sola familia, muy característico).
  • Hero como sesión de terminal con cursor parpadeante; comandos con animación de tecleo.
  • Paleta: verde terminal + ámbar sobre negro; resto de secciones con detalle tipo prompt.
Riesgo: muy personal y muy "dev de verdad", pero el verde intenso pide un uso contenido para no saturar.

Qué cambia:
  • Aquí el mono deja de ser la estrella y se combina con un display (Archivo) — la web "se ve" más producto.
  • Vocabulario git visible: historial de commits en el hero, tarjetas como PRs con issue numbers y estados.
  • Paleta estilo GitHub dark (azul + verde + violeta); la más sobria de las tres.
Ventaja: la que menos riesgo visual tiene y mejor envejece, a cambio de impactar algo menos.
Los tres se aplican igual: solo piel visual sobre la estructura actual (Hero, About, Projects, Skills, Contact), manteniendo contenidos, animación con framer-motion y deploy en develop. Dime "A", "B" o "C" (o mezcla de detalles) y lo implemento.
